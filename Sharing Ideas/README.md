## 📝 How to Share an Idea

### 1. 创建 Idea 文件

每个研究想法单独创建一个 Markdown 文件（`.md`）。

**统一命名格式：**

`IDEA-编号-想法名称-成员缩写.md`

例如：

- `IDEA-001-公交辅助无人机配送-lzy.md`
- `IDEA-002-大规模客户分组优化-lzy.md`
- `IDEA-003-动态配送策略-ry.md`

其中：

- **编号**：按照提交顺序统一编号，避免重复。
- **想法名称**：简洁概括研究主题。
- **成员缩写**：使用提出人的姓名缩写，例如 `lzy`、`ry`、`wh`。

如果一个想法由多位成员共同提出，可以在文件名中包含多位成员的缩写，例如：

`IDEA-004-联合路径优化-lzy-ry.md`

### 2. 填写 Idea 内容

建议按照以下模板记录，内容不必过于正式，初步想法也可以先提交，后续逐步完善。

## 📄 Idea Template

**Idea Title：**

**Contributor：**

**Date：**

**Status：** 初步想法 / 讨论中 / 验证中 / 已完成

### 1. Background

描述研究背景、当前存在的问题，以及产生该想法的原因。

### 2. Core Idea

介绍核心研究思路，包括拟解决的问题、可能采用的方法或改进方案。

### 3. Potential Contributions

说明预期研究价值、可能的创新点或实际应用意义。

### 4. Related Work

列出相关论文、参考资料或链接。

### 5. Open Questions

记录尚未解决的问题，以及希望与其他成员进一步讨论的内容。

## 📋 How to Update the Idea List

提交新的 Idea 后，请同步更新本 README 中的 **Idea List**，包括：

1. Idea 编号与标题。
2. 对应 Markdown 文件的链接。
3. 提出人（Contributor）。
4. 提出日期（Date）。
5. 当前状态（Status）。

随着研究推进，可以及时更新 Idea 的状态。

## 💬 Discussion & Collaboration

- 欢迎所有成员阅读并讨论其他人的想法。
- 建议通过 GitHub Issues 进行交流，避免直接覆盖其他成员的内容。
- 讨论形成的重要结论，可以补充到对应的 Idea 文件中。
- 修改他人提出的 Idea 时，请保留原始提出人的署名。
- 如果有新的共同贡献者，可以在文件内容中补充其姓名或缩写。

## 🤝 Guidelines

1. 鼓励分享尚未成熟的研究想法。
2. 每个 Idea 使用独立文件，避免多个想法混在一起。
3. 文件名必须包含提出人的姓名缩写，明确想法来源。
4. 尽量避免重复提交已有想法。
5. 尊重原创想法，鼓励开放讨论与合作完善。
